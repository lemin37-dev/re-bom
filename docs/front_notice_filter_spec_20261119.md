# 공고 상세 · 필터 화면 "자리" 만들기 — CLI 전달용 v3 (2026-11-20, 사용자 결정 반영)

대상: 프론트 저장소(https://d2tvhldw6ss6yp.cloudfront.net/ 로 배포되는 Next.js 앱)
목적: 지금은 2026-10-30 공고 샘플이라 Silver 정제 칼럼·Jev·비전 태그가 없다. **실제 데이터가 들어오면 값만 채워지도록 화면 자리와 필터 자리를 먼저 만든다.**
이전 판과 달라진 점은 맨 아래 "변경 기록"에 있다.

## 0. 원칙

1. **화면 컴포넌트는 칼럼 이름을 직접 쓰지 않는다.** API 응답 → `AnimalDetailView`(2장) 변환 함수 `src/lib/animal-adapter.ts` 한 곳만 필드 이름을 안다. Silver 이름이 확정되면 이 파일만 고친다.
2. **모든 자리는 `값 + 상태 + 출처`를 받는다.**
   - 상태: `ok` 표시 · `none` "보호소 기록이 없어요" · `pending` 아직 없는 데이터(숨김, 개발 모드에서만 "준비 중") · `hidden` 보여 주지 않기로 한 것
   - 출처: `notice` 공고 원문 · `silver` Silver 정제값 · `jev` · `vision` · `breed_table` 품종 정보 · `llm` 문장 다듬기
3. **'기록 없음'을 '이상 없음'으로 바꾸지 않는다.**
4. **자동으로 만든 값(Jev·비전·LLM)에는 출처 표시를 붙인다**: "보호소 기록을 바탕으로 자동 분류했어요".
5. **결정되지 않은 규칙은 설정 파일(`src/config/notice.ts`, `src/config/filters.ts`)에 둔다.** 코드에 박지 않는다.
6. **정제 규칙은 Silver가 맡는다.** 프론트는 kg 변환·크기·털색 계열을 직접 계산하지 않고 Silver 값을 그대로 보여 준다. 지금 샘플에 값이 없으면 `pending`이다.
7. 개인정보
   - 보호자 이름(careOwnerNm)·담당자 칼럼은 view model에 넣지 않는다.
   - 보호소 전화는 **공공기관 번호라 화면에 보여 준다** (방문 전에 연락할 방법이 있어야 함). 지금처럼 상세 "보호소에 문의하기"에서 보호소 이름·전화번호를 보여 주고 `tel:` 링크로 바로 걸 수 있게 한다. 나중에 지도(보호소 위치)를 같은 자리에 붙인다 (11-20 사용자 결정). 검색 요청·로그·분석 이벤트로는 보내지 않는다.
   - 문서·샘플에는 가짜 번호(`000-0000-0000`)만 쓴다.
   - 발견 장소는 읍·면·동 또는 구까지만 보여 준다. 세부 주소(지번·번지·도로명 번호)는 화면에 쓰지 않는다 (3장).
8. **하지 않을 것**: 백엔드 API·DB·Silver 변경, 실제 데이터 연결, 배포. PR까지만 하고, 머지·배포는 승인 후.

## 2. view model (프론트 타입 초안)

```ts
// src/types/animal-view.ts — 화면은 이 타입만 씀. 변환은 src/lib/animal-adapter.ts 한 곳에서
export type SlotStatus = "ok" | "none" | "pending" | "hidden";
export type SlotSource = "notice" | "silver" | "jev" | "vision" | "breed_table" | "llm";
export interface Slot<T> { value: T | null; status: SlotStatus; source: SlotSource; version?: string }

export interface PhotoView {
  url: string;                    // https로 바꾼 원본 URL (4장)
  slot: number;
  sha256?: string;                // 사진 벡터와 잇는 키 (비슷한 아이들 · 나중에 사진 점검을 붙일 때)
}

export interface AnimalDetailView {
  id: string;
  header: {
    speciesBreed: Slot<string>; sex: Slot<"M" | "F" | "Q">; neuter: Slot<"Y" | "N" | "U">;
    birthYear: Slot<number>;      // 나이(N살)·60일 미만은 화면용 값으로 만들지 않음
    state: Slot<string>;
  };
  appearance: {
    weightText: Slot<string>; size: Slot<"소형" | "중형" | "대형">; breedTypicalSize: Slot<string>;
    colorFamilies: Slot<string[]>; colorRaw: Slot<string>; pattern: Slot<string[]>;
    imageFeatures: Slot<{ label: string; value: string }[]>; breedTypicalFeatures: Slot<{ label: string; value: string }[]>;
  };
  persona: { raw: Slot<string>; tags: Slot<{ tag: string; negative: boolean }[]>; soft: Slot<string> };
  health: { raw: Slot<string>; vaccination: Slot<string>; tags: Slot<string[]> };
  notice: { noticeNo: Slot<string>; start: Slot<string>; end: Slot<string>; happenPlace: Slot<string>; org: Slot<string> };
  shelter: { name: Slot<string>; tel: Slot<string> };
  photos: PhotoView[];
  summary: Slot<string>;
  breedInfo: Slot<{ name: string; size?: string; coat?: string; origin?: string; links: { label: string; url: string }[]; sources: string[] }>;
}
```

## 3. 위치 정보

- **발견 장소**: 화면에는 읍·면·동 또는 구까지만 보여 준다 (설정 `HAPPEN_PLACE_LEVEL = "dong"`).
  - 세부 주소(지번 `136-57` · `701번지` · 도로명 번호 `○○길 8`)는 일부 공고에만 있다. 특이사항이 있거나 지자체가 자세히 적은 경우다.
  - 몇 건에 있는지, 발견 장소인지 보호소 위치인지는 아직 확인 전이다 → Silver 점검(`silver_schema_check.py`의 "발견 장소 세부 주소 모양" 항목)으로 센다.
  - 처리 방향 (사용자 결정): 세부 주소가 있으면 화면·API 응답에서는 걸러 내고, 원문은 내부 계산용으로만 Silver에 보관한다(정제 대상).
  - 지금 샘플 `/api/animals` 응답에는 지번까지 담겨 브라우저로 내려온다 (실측). 화면에서만 자르면 네트워크 응답에 남으므로 최종적으로는 API(Gold)가 정제된 값만 보내야 한다 → Silver·백엔드 담당 항목.
  - 프론트는 그 전까지 adapter에서 읍·면·동/구까지 한 번 더 자른다 (안전장치).
- **보호소 위치**: 지도·거리 계산용 정확한 위치는 내부에서만 쓴다. 보호소 주소를 네이버 플레이스·카카오 API로 좌표로 바꾸는 일은 백엔드에서 한다. 공공 API 주소는 시·군·구까지라서 필요하다. 프론트는 `shelter.lat/lng` 자리만 둔다 (`pending`).

## 4. 사진 · 60일 미만

- **사진**: 팀 합의대로 Silver의 원본 이미지 URL을 쓴다.
  - 사진 점검(동물 없음·공고와 다른 사진)은 이번 범위에서 하지 않는다. 2만 건이 넘는 공고 중 사진과 공고가 다른 경우가 4건이라, 5건 이상일 때 작업하기로 한 팀 결정이다. PhotoView에 sha256 키만 남겨 둔다.
  - 공고에 사진이 없으면 "사진 없음" 그림을 보여 준다.
  - adapter에서 `http://openapi.animal.go.kr/...`를 `https://`로 바꾼다.
    - 지금 콘솔에 Mixed Content 경고가 약 20건 있다.
    - 바꾼 뒤 사진이 깨지면 원래대로 되돌리고 보고한다.
- **60일 미만**: 화면에 쓰지 않는다 (사용자 결정).
  - 이유: 공고 뒤에 태어난 동물, 출생 연도는 2024인데 '60일 미만'으로 적힌 공고 등 믿을 수 없고 갱신되지 않는 값이 있다.
  - '성장 중' 배지·안내를 만들지 않는다. 나이는 출생 연도만 보여 준다.

## 5. 필터 자리

### 5.1 설정 파일로 만든다

필터 패널은 `src/config/filters.ts`를 읽어서 그린다.

```ts
export interface FilterDef {
  key: string; label: string; multi: boolean; enabled: boolean;
  options: { value: string; label: string }[];
  column: string | null;          // Silver 칼럼 (확정 전 null)
  unknownValues: string[];        // 이 값이면 '미상' → 더보기 단계 + 확인 필요 안내
  note?: string;                  // 패널 아래 작은 안내
}
```

| key | 라벨 | 선택지 | 미상 값 | 비고 |
|---|---|---|---|---|
| region | 지역 | 전국 · 서울·경기 · 인천 · 강원 · 충청 · 전라 · 경상 · 제주 | — | 지금과 같음 |
| species | 축종 | 전체 · 개 · 고양이 | — | **'기타'는 실제 데이터에서 빠진다** → 선택지에서 뺌 |
| age | 나이 | (화면에서 뺌) | — | **내부 보류 · 지금은 쓰지 않음** (`enabled: false`). 출생 연도만으로는 월을 몰라 같은 연도의 1월생·12월생이 다음 해에 함께 '1살 이상'이 된다. 또 나이 때문에 맞는 아이가 안 보이면 안 된다 (사용자 결정) |
| size | 크기 | 상관없음 · 소형 · 중형 · 대형 | 몸무게 없음 | 라벨: `소형 10kg 미만 · 중형 10~25kg 미만 · 대형 25kg 이상` (Silver 규칙, 확정). 9.5kg처럼 소수 몸무게가 있으므로 `~9kg`보다 `10kg 미만`으로 적는다. Silver size 값으로 거름. 개에만 |
| sex | 성별 | 상관없음 · 수컷 · 암컷 | Q | |
| neuter | 중성화 | 상관없음 · 함 · 안 함 | U | **새로 추가.** '함'이면 Y 먼저, U는 더보기에 안내와 함께, N은 뺌 |
| color | 털색 | 상관없음 · 검정 · 노랑 · 갈색 · 흰색 · 회색 · 기타 | 기타 | **새로 추가.** 계열 기준. 여러 개 고를 수 있게(고른 색 중 하나라도 있으면 포함) — 설정 `COLOR_MULTI = true`, 한 개만이면 false |
| state | 보호 상태 | 보호중 (고정) | — | 화면에 노출하지 않음 |

- 성격은 필터로 만들지 않는다. 성격은 문장 검색이 맡는다.
- 패널 위 요약 칩("전국 · 전체 · 무관")은 켜진 필터를 모두 보여 준다. 예: `충청 · 개 · 소형 · 중성화 함 · 흰색`.

### 5.2 결과 화면 자리

- **정렬**:
  - 검색어나 사진이 있으면 **추천순만** 쓴다 (백엔드가 정한 순서: 필터 단계 + 사진 유사도 + 글 유사도). 정렬 선택 상자를 숨긴다.
  - 조건만 고르고 둘러볼 때는 지금처럼 최신 공고 순 · 공고 종료 임박 순.
  - 거리순(보호소 위치 기준)은 자리만 두고 끈다 (`enabled: false`). 위치 좌표가 생긴 뒤 필요성을 다시 정한다.
- **미상 단계**: 조건이 모두 맞는 친구 → (더보기) 미상이 있는 친구. 미상 카드에는 무엇이 비었는지 문장으로 보여 준다.
  - 예: "공고에 중성화 여부가 없어 확인이 필요한 친구예요"
  - '알 수 없음'·'확인 안 됨' 같은 짧은 말은 쓰지 않는다.
- **토글**: 처음부터 보여 주지 않는다. 응답에 `exhausted: true`가 오면 그때 안내와 토글을 보여 준다.
  - `exhausted: true`는 백엔드가 "지금 조건으로 잘 맞는 결과를 다 보여 줬다"고 판단한 경우다.
  - 안내 예: "조건에 잘 맞는 친구를 모두 보여 드렸어요. 특징과 생김새 중 더 중요한 쪽을 골라 이어서 찾아볼까요?"
  - 토글: `특징 중심 — 성격·특징 글을 더 반영해요` / `생김새 중심 — 사진을 더 반영해요`
  - 프론트는 `mode=feature|look`과 이미 본 공고 id(`seen`)만 보낸다. 끝났는지 판단하는 기준(유사도 하한, 개수 한도)과 가중치는 백엔드 설정이다.
- **장애**: 응답에 `fallback: true`가 오면 결과 위에 "지금은 문장·사진 분석이 잠시 어려워 조건으로만 찾았어요". 글과 사진 검색이 모두 같은 임베딩 API를 쓰므로 둘 다에 적용한다.

### 5.3 쿼리 이름 충돌 (실측)

지금 목록 API는 `size`를 **페이지 크기**로 쓴다 (`/api/animals?state=protect&sort=latest&page=1&size=8`). 크기 필터를 `size`로 넣으면 충돌한다. 페이지 크기를 `limit`으로 바꾸거나 크기 필터를 `bodySize`로 한다. 어느 쪽인지 백엔드 담당과 맞춘다.

## 7. 작업 순서 (CLI)

1. 지금 코드에서 상세 섹션 컴포넌트, 카드 컴포넌트, 필터 패널, 정렬, `/api/animals` 응답 타입이 어디 있는지 찾아 **먼저 보고**한다 (파일 경로 · 지금 쓰는 필드 · 카드에서 나이를 쓰는 곳).
2. `src/types/animal-view.ts`, `src/lib/animal-adapter.ts`를 만든다. 지금 샘플 API 응답을 view model로 바꾸고, 없는 값은 `pending`이나 `none`으로 둔다.
3. 1장 자리를 컴포넌트로 만든다. 빈 상태 4가지를 모두 처리한다. 카드에서 나이를 뺀다.
4. `src/config/notice.ts`(HAPPEN_PLACE_LEVEL · PERSONA_DISPLAY · PRIVACY_NOTE_TRAINING)와 `src/config/filters.ts`를 만들고, 필터 패널을 설정으로 그린다 (중성화·털색 추가, 기타 축종 제거, 나이 필터 숨김).
5. 5.2 결과 자리를 만든다: 추천순, 미상 안내, `exhausted` 토글, `fallback` 안내. 지금은 백엔드가 없으니 fixtures로 각 상태를 확인한다.
6. `fixtures/animals.sample.json` 4마리로 화면을 확인하고 스크린샷을 남긴다.
7. PR을 연다 (배포 안 함). PR 설명에 결정 필요 항목과 현재 기본값을 표로 적는다.
